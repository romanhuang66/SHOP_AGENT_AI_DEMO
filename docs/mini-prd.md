## 1. 定位与目标

ShopAgent 是基于大模型、RAG 与 Agent 的智能购物和售后服务 Web App，覆盖消费者对话助手与企业运营后台。
首版面向数码商品，以演示商品和订单完成可操作的购物决策、订单查询与售后闭环。

目标用户：需要比较商品、了解订单和售后政策的消费者；需要维护知识、查看会话和评估服务效果的电商运营人员。

首版目标：用户能提出需求、得到有商品依据的推荐、继续比较、查询本人演示订单并提交售后工单；运营能更新知识并验证其检索效果，追踪实际会话、反馈与评测结果。

本文为实施规格，不代表功能已经完成。简历描述以最终验收的实际能力为准；用户提供的项目日期不作为开发或测试记录日期。

## 2. 范围与业务边界

| 范围 | 首版实现 |
| --- | --- |
| C 端 | 多轮对话、流式回答、推荐、最多三款商品比较、模拟订单及物流、售后咨询、反馈、语音输入与朗读、人工转接工单 |
| B 端 | 管理员登录、知识库管理、Prompt 版本、会话与调用记录、反馈与工单、评测、数据看板 |
| Agent | LLM API、结构化工具调用、上下文与偏好记忆、知识检索及引用 |
| 数据 | 约 30 款数码商品、10 笔模拟订单、物流轨迹、售后政策与 FAQ |

模拟订单仍通过真实程序查询数据，并校验演示用户归属。人工转接指生成工单及后台处理，不承诺即时人工响应。商品价格、库存和物流均标注演示用途。

## 4. 核心流程与交互
### 4.1 购物推荐与比较

用户输入“推荐 500 元以内的降噪耳机” → 服务端读取当前会话及预算偏好 → 模型识别约束并调用商品检索 → 工具返回实际数据中的候选商品 → 模型结合检索结果说明推荐理由 → 页面渲染带价格、规格和详情入口的卡片。

用户继续说“通勤用，更看重续航”，应沿用耳机品类及 500 元预算；只有明确改变约束才覆盖。若约束互相冲突或必要信息不足，先澄清。无符合商品时说明未找到，并建议用户选择是否放宽条件，不擅自突破预算。

用户选择 2–3 款进入比较；模型提出的商品 ID 必须由服务端验证，价格与规格从商品数据读取。比较支持删除和替换，达到三款后给出明确提示。

### 4.2 订单与物流

用户询问本人演示订单 → 服务端从签名会话确定演示用户身份 → 工具按订单号和归属查询 → 展示状态、商品、金额及物流轨迹。缺少订单号且存在多笔订单时提供选择。

订单不存在或不属于当前用户时统一提示无法查询该订单，不展示他人信息。允许新访客建立独立演示身份，避免仅凭订单号查询任意订单。

### 4.3 售后与人工转接

用户咨询退货、换货或保修 → 检索已发布政策 → 展示带来源和版本的回答。缺少购买时间、商品状态等条件时询问必要信息；不编造退款批准或退款到账时间。

用户请求人工帮助或问题无法解决 → 展示工单摘要 → 用户点击提交 → 返回工单号及“待处理”状态 → 管理员可改为处理中或已解决并填写备注。避免重复提交同一请求。

### 4.4 网页语音

用户点击麦克风 → 浏览器请求授权 → 显示录音状态及停止按钮 → 识别结果填入输入框 → 用户检查并发送 → 走同一对话流程。回答提供手动朗读与停止按钮，默认不自动播放。

权限拒绝、无麦克风、识别失败或浏览器不支持时显示具体提示，保留文字输入。浏览器语音服务的地区可用性必须实测；若无法通过语音验收，单独提出服务端 ASR 接入方案及所需配置，不能把不支持状态视为语音功能已完成。

### 4.5 知识维护

管理员新建、编辑或导入 TXT/Markdown → 预览标题与正文 → 保存新版本 → 分块及向量化 → 索引成功后发布 → 检索预览验证 → 后续对话使用最新已发布版本。

导入默认限制 1 MB，校验文件类型及正文长度。索引失败保留可重试状态；更新期间旧版继续可用；禁用或删除后不再参与新检索。历史会话保存引用快照。首版不解析 PDF、Word 或扫描图片。

### 4.6 Prompt 与评测

管理员编辑 Prompt 草稿 → 保存不可变版本 → 在评测页选用草稿版本试运行 → 查看结果 → 启用版本。回滚重新选择旧版本；每次对话和评测记录实际使用版本。Prompt 修改不允许绕过服务端身份校验和工具权限。

评测运行以小批次、有限并发执行，保存进度并允许失败项重试；避免把整批测试放进单个长时间请求。

## 5. AI 与 RAG 方案

技术栈：Next.js、TypeScript、Tailwind CSS、Supabase Auth/PostgreSQL/pgvector、Vercel。安装时选择兼容且受支持的版本并锁定依赖；当前本机 Node.js 版本需在搭建时与选定框架核对。

RAG 流程：正文清洗 → 按标题和段落分块（初始目标每块约 500 个中文字符，重叠约 80 字符）→ Embedding → 向量检索 → 按可用商品、已发布知识和权限过滤 → 返回前若干相关片段 → 模型带引用回答。分块、Top K 和未命中阈值属于待评测参数，不预设为最优。

商品推荐工具使用结构化预算、品类和规格筛选，避免仅靠向量相似度判断价格。知识片段是不可信数据，不执行其中的指令。引用编号必须对应本次检索片段，前端可查看来源标题、正文摘录与版本。

拟定工具：`search_products`、`compare_products`、`get_order`、`get_logistics`、`search_knowledge`、`create_support_ticket`。全部在服务端校验参数、身份和结果；工单工具必须有用户明确提交操作；设置调用轮次、超时和有限重试，避免循环。

记忆仅用于当前用户的当前会话及明确提取的购物偏好；新建会话重置任务上下文，支持删除本人会话。保存完整历史但按上下文预算发送最近消息与摘要，记录摘要更新时间。不同用户之间不得共享记忆。

真实模式需要对话模型和 Embedding 服务配置。演示模式使用明确标注的预设逻辑和数据，不计入真实模型评测。服务配置错误时明确提示真实服务失败，不静默伪装为真实 AI 回答。

## 6. 数据与访问控制

| 数据实体 | 主要字段/用途 |
| --- | --- |
| products | ID、名称、品类、价格、规格、库存、图片、演示标记 |
| orders / order_items / logistics_events | 演示用户归属、状态、商品快照、金额、物流事件 |
| conversations / messages | 用户归属、消息、结构化结果、引用快照、模式、模型与 Prompt 版本 |
| conversation_memory | 用户与会话归属、偏好、摘要及更新时间 |
| knowledge_documents / versions / chunks | 来源、正文、版本、发布状态、分块、向量及索引状态 |
| prompt_versions | 内容、创建人、启用状态与时间 |
| tool_calls / model_calls | 参数脱敏摘要、状态、耗时、Token、错误码及关联会话 |
| feedback / support_tickets | 用户归属、评价、原因、状态、处理备注 |
| evaluation_cases / runs / results | 输入、预期证据和工具、运行配置、自动结果、人工标注 |

管理员使用 Supabase Auth 登录及受保护的管理员角色；公共用户没有后台权限。演示用户采用服务端验证的匿名身份或签名会话，不信任客户端提交的用户 ID。数据库启用适用的 RLS，服务端也执行归属检查。

模型及数据库管理密钥仅保存在服务端环境变量，不使用前端公开变量。记录中不保存密钥；公共接口限流，输入、输出及工具参数限制长度。持久化依赖 Supabase，不使用 Vercel 本地文件存储会话。

## 7. 指标口径与目标

以下为首版验收目标，不是已取得的结果。无数据时显示空状态或“暂无数据”。示例看板需单独标注，不能混入实测指标。

| 指标 | 统计方式 | 初始目标 |
| --- | --- | --- |
| 回答准确率 | 人工判为准确的回答 / 已人工标注回答；记录标注理由 | 核心用例 ≥85% |
| 任务成功率 | 满足预定任务完成条件的用例 / 已完成判定的用例 | ≥85% |
| 工具调用成功率 | 有效完成的调用 / 所有已结束调用；合法未查到也单独记录业务结果 | ≥95% |
| 响应时长 | 服务端请求接收到首个可见输出、完整结束；分别展示中位数和 P95 | 先实测建立基线 |
| Token | 模型服务返回的输入/输出用量；缺失时显示未知 | 完整记录可获取项 |
| 模型费用 | Token × 对应模型单价与币种；Embedding 单列 | 标注为估算 |
| 用户反馈 | 好评、差评、未评价分开；好评率以已评价回答为分母 | 展示样本数 |

看板默认最近 7 天，允许切换最近 30 天；按北京时间划分日期。评测流量与实际用户流量分开，失败和重试不被吞掉。含引用不等于准确，模型自评不作为人工准确率。

## 8. 异常机制

| 场景 | 产品行为 |
| --- | --- |
| 模型超时、限流或不可用 | 保留用户消息，显示重试；记录错误；限制重试次数 |
| 知识未命中 | 明确信息不足，提供补充问题及人工工单入口 |
| 工具参数不合法 | 服务端拒绝并记录；引导补充有效条件 |
| 工具查询失败 | 区分业务未查到和服务故障；不生成虚假状态 |
| 流式回答中断 | 标记未完成，允许重试，不把半段回答记为成功 |
| 数据库不可用 | 明确保存失败；不显示已保存或已提交 |
| 未授权后台访问 | 拒绝数据及写入请求，引导登录 |
| 删除知识或会话 | 要求明确删除操作；更新页面与检索；保留必要的脱敏审计统计 |

## 9. 交付与阶段门槛

第 2 步交付本文档、流程图和验收清单；等待用户批准后进入第 3 步界面制作。第 3 步可先使用明确标注的界面示例数据，但不声称已接入模型或数据库。

后续需要 Vercel 账号授权、Supabase 项目配置、对话模型与 Embedding 服务配置。语音服务如需付费 ASR，单独说明并确认。所有收费套餐和第三方账号操作须在具体选择后处理，不在本文档中默认购买。

上线门槛：构建成功、核心流程及权限检查通过、真实模式完成验证、语音能力与限制实测、环境变量配置完成、线上页面与接口验证通过。未通过项如实记录，不能用演示模式替代真实模式验收。
